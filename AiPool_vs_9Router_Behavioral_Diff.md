# AiPool vs 9Router Behavioral Comparison & Diff Matrix

| Area | 9Router Behavior | AiPool Legacy Policy | Conflict? | Architectural Action Required |
|---|---|---|---|---|
| **Account Selection** | Multi-strategy: `fill-first` (priority order) or `sticky round-robin` (configurable sticky limit e.g. 3). Concurrency mutex (`selectionMutex`). Excludes in-flight failed accounts (`excludeConnectionIds`). | Single active pointer on disk (`<store>/active`). Rotates sequentially from active slot. In-memory `fcntl.flock` on switch. | **YES** | Adopt 9Router's candidate ordering: prioritize healthy accounts, enforce in-flight failure exclusion set, and support sticky round-robin with configurable threshold without global lock contention. |
| **Quota Exhaustion Signals** | Matches text substrings (`"rate limit"`, `"too many requests"`, `"quota exceeded"`, `"capacity"`, `"overloaded"`) and status codes (429, 403, and **409 Conflict** on Antigravity). Peeks SSE stream for `"model_at_capacity"`. | Matches 429 and 403 only. Completely ignores Antigravity **409 Conflict** and SSE in-band capacity strings. | **YES** | Update `bridges/error_taxonomy.py` and bridge parsers to recognize HTTP 409 and in-band `"model_at_capacity"` as quota exhaustion triggers. |
| **All-Accounts-Exhausted Handling** | Computes earliest `retryAfter` timestamp across all locked accounts; fast-rejects with HTTP 503 + `Retry-After: <sec>` header. Does **NOT** hammer upstream. | Executes `POOL.candidates(model, False) or POOL.candidates(model, True)`. If all accounts are in cooldown, it retries all of them upstream in a 429 storm! | **YES (CRITICAL)** | Eliminate `include_cooldown=True` storm fallback. When all accounts are in cooldown, return HTTP 503 immediately with earliest `Retry-After`. |
| **Account-Wide vs Per-Model Lock** | Distinct `modelLock_${model}` and `modelLock___all`. Rate limit on one model locks only that model on the account. Auth/plan errors lock `modelLock___all`. | Keyed strictly on `(provider, account, model)`. 401 token revocation only cooled down the current model; other models continued trying the dead account. | **YES** | Add account-wide lock support (`__all__`) in `pool_runtime.py` alongside per-model locks. |
| **Cooldown Duration & Backoff** | Respects upstream `resets_at` / `resets_in_seconds` / `Retry-After`. Rule-based exponential backoff: base 2s, 4s, 8s, 16s... max 300s. Transient 5xx: 30s. Fixed 401-404: 120s. | Hardcoded 60s fallback floor (`retry_seconds()` defaults to 60s). High-concurrency burst 429s unnecessarily take accounts offline for a whole minute. | **YES** | Implement 9Router exponential backoff (base 2s, max 300s) and parse upstream reset headers/timestamps directly without 60s floor. |
| **Retry Policy (Zero-Retry)** | Layer 1 transport retries on same account for 502/503/504 (2-3 attempts, 2-3s delay) and network drops. Mid-flight token refresh retry on 401/403. | Strict "Zero-Retry": `attempts = 1`, `retry_delay = 0.0`. Any transient 5xx or network disconnect immediately terminates request. | **YES** | Abolish Zero-Retry policy. Add bounded transport retries (2 attempts, 2s backoff) for transient 502/503/504 and network drops before failing over candidate account. |
| **Account Failover on 429** | HTTP 429 unconditionally sets `shouldFallback: true`. Failed account gets cooldown, request immediately routes to next available account. | Classified 429 without explicit quota string as `TEMP_RATE_LIMIT` with `failover: false`. Requests failed without trying other accounts! | **YES** | Enable failover for all 429 rate limits across pool candidates. |
| **Circuit Breaker** | Account-isolated locks (`connectionId` + `model`). Never locks other accounts. In-memory 3-strike breaker on Antigravity for quota desync. | Global `ModelCircuitBreaker` keyed on `(provider, model)`. One account 429/503 opened breaker for 45s, fast-rejecting ALL healthy accounts for that model! | **YES** | De-globalize `ModelCircuitBreaker` so it tracks per-account, or retire it in favor of 9Router's per-account model locks. |
| **Streaming (Gemini / Antigravity)** | True SSE streaming via `streamGenerateContent?alt=sse`. Incremental token delivery in 1-2s (TTFT < 2s). | Calls non-streaming `generateContent` and blocks synchronously for up to 120s before sending any bytes! Clients timed out at 75s. | **YES (CRITICAL)** | Migrate `gemini_bridge.py` to native SSE (`streamGenerateContent?alt=sse`) with incremental chunk delivery. |
| **Empty Response Elimination** | Buffers initial upstream events before sending HTTP 200 OK headers. If upstream fails/empties, returns HTTP 502/400 JSON error, never 200 OK + empty body. | Sent HTTP 200 OK headers immediately, then if content was empty/filtered, emitted empty delta + stop (200 OK + empty response). | **YES (CRITICAL)** | Buffer first content/reasoning chunk before flushing HTTP 200 headers. If empty, return error status code. Discard empty deltas. |
| **Idle Timeout (Codex)** | Decoupled byte watchdog: 360s timeout on raw upstream bytes. Avoids false aborts during long o1/o3/gpt-5 reasoning. | Hardcoded 30s socket timeout (`CODEX_CHUNK_IDLE_TIMEOUT=30`). Thinking models aborted prematurely with timeout. | **YES** | Increase chunk idle timeout to 180s-360s and reset watchdog on any incoming byte activity. |
| **Terminal Framing on Abort** | Chat completions: `data: {"error": ...}\n\ndata: [DONE]\n\n`. Responses API: `event: response.failed...` (NEVER sends `[DONE]` to Responses API). | Emitted `data: [DONE]` unconditionally on abort, which crashed Responses API client parsers. | **YES** | Differentiate terminal abort format between `/v1/chat/completions` and `/v1/responses`. |
| **Auth Token Refresh** | Proactive check (5m lead time), background scheduler tick, in-flight mutex per account to prevent `refresh_token_reused`. | On-demand check and refresh. Can race under concurrent requests for same account. | **YES** | Add in-flight account refresh lock to prevent concurrent duplicate refresh calls. |
